# Validation — 1.0.1 hardlink correction

The v1.0.0 inventory guard incorrectly rejected legitimate regular-file hardlinks. Read-only inspection found an active account save sharing a file identity with three native save-backup entries, with no symlink/junction/reparse attributes. The transaction work file had matching content but a different identity. This demonstrates native backup sharing; filesystem metadata alone cannot prove the process that created the links. No restricted NX2navi code was inspected.

The corrected local full suite passed **56 tests, with 1 skipped** because Windows denied symlink creation. Real junction and hardlink tests passed. The revised synthetic GUI smoke routine also passed hardlink preview, independent-copy checks and restoration of original hardlink topology. The GitHub Actions candidate's `test-summary.json` and `frozen-smoke-results.json` report the authoritative clean-runner results for its exact executable.

New coverage includes regular files; multiple paths with the same device/file identity; identical bytes with different identities; read-only preview; native snapshot links; an externally linked source and account.uid; fresh independent copies with preserved timestamps; refusal to write existing hardlinked destinations; distinct identities for each external backup file; post-transfer native links; rollback preserving the complete original profile and its hardlink topology; externally changed archives; link injection into staging; hardlinked lock files; nonregular types; and reparse attributes. Existing missing-file, wrong-title, stale-preview, process guard, interruption, traversal, symlink/junction, GUI and thumbnail tests remain enabled.

Content manifests intentionally contain hashes, sizes and directory membership, not physical file identities. Independent copies necessarily have different IDs and link counts. Physical IDs are used only for runtime safety checks and are not required to match backup contents. Schema-1 rollback remains compatible. Original profiles are preserved intact by no-overwrite rename; external backups materialize each path as an independent file. account.uid bytes remain unchanged.

The only candidate workflow trigger is workflow_dispatch. Repository token permission is contents: read. The workflow builds the EXE, executes the full synthetic suite and a frozen hardlink transfer/rollback test, audits the allowlisted package and embedded archives, then stores EXE/ZIP/SHA-256/report files as Actions artifacts. It has no release creation or publication command. Public publication requires separate user approval.

Privacy: actual save files, account identifiers, file IDs, local machine paths and private diagnosis evidence are not included. Raw XML and GUI screenshots are excluded from candidate artifacts. Generic Windows/vendor runtime paths are not individual machine paths. Reports contain synthetic test results only.

Limits: no real migration is performed for this fix. No new gameplay/save-reload compatibility claim is made. A malicious same-user process can still race file-system checks, and external applications must stay closed during a transfer. If an external alias changes the preserved original, rollback refuses it and retains the verified independent backup for reviewed recovery. The EXE is unsigned.
